# Pixel view layout: output-plan base vs sample-precision evidence (2026-10-28)

Structural `size_of` / `align_of` only. This is not a heap, allocation or RSS measurement.

- Host r7900x, `x86_64-unknown-linux-gnu`, rustc 1.99.1 (58cf8f9c3 2026-10-13), dev profile,
  zenpixels default features.
- Base: `86d0e2d30406a006bf8332f142029b7f58353086` (output-plan, PR #92), exported with `git archive`.
- Head: the zenpixels crate as of `68e463bdb21c273fd6f9f697cc20c1765f759f9e`, unchanged through
  `0c96114e81cbecf086952fc75e5bf696e5d81cd9` (PR #95).
- Probe sources: `benchmarks/layout-probe/base.rs` and `head.rs`, byte-identical to the measured run.
- Measured 2026-10-28T02:17:45Z-02:17:47Z, one run each:
  `CARGO_TARGET_DIR=<scratch>/target cargo run --offline -q --manifest-path <scratch>/probe-base/Cargo.toml`,
  then the same for `probe-head`. Each manifest declared only `zenpixels = { path = ... }` (the
  exported base tree, or the review workspace) and an empty `[workspace]`.
- Reproduce: `just layout-probe` (or `benchmarks/layout-probe/run.sh [BASE_REV]`), which performs
  the same steps without `--offline`. The script was written from those steps after the run; the
  numbers below come from the run itself.

| type | base size | base align | head size | head align |
|---|---|---|---|---|
| `PixelSlice<'static>` | 48 | 8 | 56 | 8 |
| `PixelSliceMut<'static>` | 48 | 8 | 48 | 8 |
| `PixelBuffer` | 64 | 8 | 72 | 8 |
| `sample::CodePlane<'static>` | 56 | 8 | 64 | 8 |
| `PixelDescriptor` | 5 | 1 | 5 | 1 |
| `Option<Arc<ColorContext>>` | 8 | 8 | 8 | 8 |
| `sample::ExactDepth` | - | - | 4 | 1 |
| `Option<sample::ExactDepth>` | - | - | 4 | 1 |

`PixelSlice` and `PixelBuffer` gain the 4-byte `Option<ExactDepth>` field and grow by 8 bytes,
because their base fields sum to 45 and 61 bytes and leave 3 bytes of tail padding.
`PixelSliceMut` carries no evidence and is unchanged. `CodePlane` grows by its new
`step_words: usize`. A 2-byte field holding only the two depths would fit the existing padding by
the same arithmetic; it is not implemented or measured. Other targets (32-bit, aarch64) were not
measured.
