# `Cmyk8` on the F32 CMYK path (2026-11-05)

`Cmyk8` had its own route through `MoxCms`: the backend's F32 transform with no black-point compensation, and a different intent from `CmykF32` on some profiles. It now runs the F32 CMYK transform and rounds to 8 bits, through `U8ThroughF32`. U16 isn't involved.

Measured on `main` at `fde59b96` against this change. Host r7900x (Ryzen 9 7900X, Zen 4); not measured on Zen 5. moxcms 0.9.1. Accuracy from `cms-contract` `cmyk8_against_f32_and_lcms`; speed from `zenpixels-convert/benches/bench_cmyk8.rs`.

```sh
CMS_CONTRACT_PROFILES=<dir> cargo test --release --manifest-path cms-contract/Cargo.toml -- --include-ignored --nocapture cmyk8_against
ZENPIXELS_CMYK_ICC=<SWOP2006_Coated3v2.icc> cargo bench -p zenpixels-convert --features cms-moxcms --bench bench_cmyk8 -- --no-busy-gate
```

## Accuracy

16,384 ink values. Differences are in 8-bit codes; means are across profiles, and worst is the largest single sample. The real set is 49 CMYK output profiles (coated and uncoated offset, newspaper, CGATS). lcms2 is the imazen port, relative colorimetric with black-point compensation at both depths.

| Profile, target | `Cmyk8` vs rounded `CmykF32`, mean / worst | | `Cmyk8` vs lcms2 8-bit, mean / worst | |
|---|---:|---:|---:|---:|
| | before | after | before | after |
| 49 real, sRGB | 17.818 / 114 | 0 / 0 | 27.535 / 185 | 13.506 / 234 |
| 49 real, Display P3 | 22.713 / 121 | 0 / 0 | 27.703 / 177 | 7.461 / 102 |
| synthetic, sRGB | 0.216 / 3 | 0 / 0 | 0.212 / 3 | 0.152 / 1 |
| synthetic, Display P3 | 0.031 / 1 | 0 / 0 | 0.193 / 2 | 0.216 / 3 |

The 234 is one sample of `Probev1_ICCv2.icc`, where F32 is also 234 from lcms2, at a mean of 123; the next worst profile is 57. moxcms and lcms2 differ on table profiles, which is expected. The remaining distance to lcms2 is the F32 path's. lcms2 refuses CMYK to RGBA here, so RGBA isn't compared with it. RGB and RGBA agree with each other in `cms_moxcms_accuracy`.

Display P3 from `CmykF32` keeps the perceptual intent without compensation, as it did. `Cmyk8` now matches it on the synthetic profile at slightly more distance from lcms2 than before, and on real profiles at much less.

## Speed

4096 pixels per call, 30 rounds, on the same host in one session. `old 8-bit path` restates the previous route with moxcms directly, in the same process, as a control.

| Build | Profile | `Cmyk8` to `Rgb8` | `CmykF32` to `RgbF32` | old 8-bit path |
|---|---|---:|---:|---:|
| `fde59b96` | synthetic | 49.8 ±0.2 µs | 365.9 ±1.1 µs | 47.1 ±0.2 µs |
| `fde59b96` | SWOP2006 Coated 3 | 50.2 ±0.6 µs | 370.5 ±2.2 µs | 47.3 ±0.3 µs |
| F32 path, `libm::powf` encode | synthetic | 376.3 ±1.6 µs | 366.7 ±2.8 µs | 47.5 ±0.6 µs |
| F32 path, `libm::powf` encode | SWOP2006 Coated 3 | 374.2 ±2.3 µs | 364.8 ±1.7 µs | 47.5 ±0.4 µs |
| this change | synthetic | 71.6 ±0.4 µs | 61.4 ±0.2 µs | 47.5 ±0.3 µs |
| this change | SWOP2006 Coated 3 | 71.4 ±0.6 µs | 61.6 ±0.4 µs | 47.5 ±0.2 µs |

`Cmyk8` costs 44% more than before, about 7.3 ns more per pixel. The encode was most of the F32 path's time, so moving it from scalar `powf` to `linear_to_srgb_extended_slice` makes `CmykF32` 6.0 times faster, and accounts for the difference from the 7.5-times cost of the first attempt. Accuracy against lcms2 held: F32's mean on the real set moved from 13.506 to 13.505.
