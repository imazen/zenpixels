Primaries, HDR headroom, CLL & CICP vs ICC

Bytes only become a real color once you know which primaries they mix, how bright 1.0 is, whether values use full or narrow range, and whether CICP or ICC is the active authority. Explore each layer visually and copy exact 0.4 Rust code below.

DiffuseWhite (white anchor)

Defines what relative linear 1.0 means in nits when crossing SDR ↔ PQ. ITU BT.2408 = 203 nits; Windows scRGB = 80 nits. Never guessed silently — pass with_sdr_white(...) or attach to ColorContext.

ContentLightLevel (MaxCLL & MaxFALL)

MaxCLL = brightest single pixel in the image/stream; MaxFALL = brightest frame-average luminance. Often missing or inflated in real files — buffer converts can measure pixels with HdrPeak::Measured, while row plans require explicit HdrPeak::Nits(...).

MasteringDisplay (SMPTE ST 2086 / mDCV)

Describes the grading monitor (primaries, white point, min/max nits like 0.0001–4000 nits) — not the content's actual peak. A 1000-nit movie graded on a 4000-nit Sony BVM still has MaxCLL = 1000.

HlgRendering (BT.2100-3 display OOTF)

HLG is scene-referred. Rendering HLG to display light needs explicit peak (Lw), black (Lb), and system gamma (e.g. HlgRendering::REFERENCE_1000_NIT). Display peak is not reused as content peak — HLG→SDR still takes explicit with_hdr_peak.

03

Signaling: Narrow vs Full range, and CICP vs ICC

Color signaling travels in container chunks before a single pixel is touched. Getting range or CICP vs ICC precedence wrong silently lifts blacks or double-applies profiles.

Signal range: Full vs Narrow (TV / studio swing)

Narrow range reserves headroom and footroom for broadcast SDI/HDMI. zenpixels-convert refuses silent Narrow↔Full conversions with ConvertError::NoPath instead of relabeling unscaled bytes (which would turn black 16 into dark gray!).

CICP vs ICC profiles — when to use each

DimensionCICP (ITU-T H.273)ICC Profile
Payload size4 bytes (CP, TC, MC, full)400 B – 2 MB (matrix/TRC or 3D CLUT)
What it expressesStandardized RGB/YCbCr (sRGB, P3, BT.2020, PQ, HLG)Arbitrary device spaces (CMYK, printers, custom LUTs, monitors)
Converter pathBuilt-in SIMD matrices (no CMS needed)Requires explicit .with_cms(&MoxCms) or &Lcms (or qualified ICC fingerprint match)
Container precedencePNG 3rd ed: cICP > iCCP > sRGB > gAMA+cHRM; AVIF: nclx vs profJPEG/TIFF: ICC primary; in ColorContext, an attached ICC stays authoritative (unusable ICC refuses rather than falling back)
SynthesisAlways emit CICP where container supports itSynthesizedIcc::for_cicp exports qualified RGB ICC (HLG ICC synthesis refused)

ColorContext vs ColorOrigin: ColorContext is the single active authority describing the current pixels in memory. ColorOrigin remembers what the original file claimed (even dual CICP + ICC chunks) for transcoding provenance — and never overrides converted pixels.
