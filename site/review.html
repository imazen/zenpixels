What the updated explorer exposes

Review candidate, 9 November 2026. These are implementation and design observations, not a release-completion claim.

The native view duplicates more than its explanation suggested

PlaneRole::CbCr and CrCb already exist. CodePlane::component reads interleaved components with individually supplied encodings. The RGB10 + alpha1 witness uses this existing component reader.

The speculative NativeCodeSlice adapter and its dependent conversion APIs have been removed at the owner’s direction. No production caller justified them. The explorer now shows the existing component-view path, without a replacement public adapter.

Signed/wide SampleEncoding descriptions, native pixel identity carriage and exact ST2086 metadata remain. Signed/wide component reading and unaligned access are not implied by those capabilities; extensions need concrete consumers.

HLG presentation was stale

The converter now supports explicit display rendering. The live panel accepts display peak, black, effective gamma and SDR white; missing conditions still refuse. The JavaScript swatch uses only the HLG OETF, so it is no longer presented as a byte oracle for display rendering. ICC synthesis remains unavailable.
