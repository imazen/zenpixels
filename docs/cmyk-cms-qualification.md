# CMYK conversion qualification

CMYK source conversion is available through the explicitly selected `Lcms`
backend (`cms-lcms`), alongside `MoxCms` (`cms-moxcms`). A source ICC is required;
CMYK values alone do not define an RGB color. This review adds test equipment,
not a new library API or a change in the default CMS. It descends from the
qualified export review af19bcda, retaining its dependency graph and kernels.
The integration owner retains the separate frozen consumer graph and failures.

## Qualified source formats

| Source → same-depth RGB/RGBA | Rust LCMS | MoxCMS 0.9.2 |
|---|---|---|
| CMYK8 | accepted | accepted |
| CMYK16 | accepted | explicit decline |
| CMYK F32, normalized ink | accepted | accepted |
| CMYK F32, inverted ink | accepted | accepted |

The prepared-row matrix covers 16 unique CMYK ICCs × two exact RGB target ICCs
× eight format pairs × two backends. All 256 LCMS cases match native C LCMS 2.20
output exactly. MoxCMS accepts 192 cases and explicitly declines 64 CMYK16 cases.
Each accepted case passes two sample-aligned strided rows of width 257, opaque
alpha, padding/suffix preservation and source immutability. An earlier deliberately
misaligned float row was refused; the failing receipt remains preserved.
Float CMYK destinations, arbitrary CMYK ICCs and all CMS/platform combinations
are not qualified by this matrix.

## Native image and CMS policy

For the same 512×512 native JXL CMYK input and independent named-sRGB reference,
Rust LCMS matches all 786,432 RGB F32 components byte-for-byte. The operation is
relative intent with CMYK black-point compensation. MoxCMS exceeds the unchanged
0.0013 normalized RGB bound in 937 components, maximum
0.006689250469207764. Its direct wrapper and codec integration agree; the CMS
reference difference remains visible rather than changing the old tolerance.

A separate common-target-ICC control disables BPC for all engines. Rust LCMS
still matches C exactly. Argyll 3.5.0/icclib 3.0 differs by at most
0.003548193722963333 normalized RGB, mean 0.000003752357372377446;
maximum quantized U8 difference is one code. Raw MoxCMS differs by at most
0.05359313450753689. These are different operations from the production
named-sRGB/BPC-on reference, so their numbers must not be mixed.

The broad float matrix uses 5,721 endpoint, axis, neutral and mixed-ink samples,
16 profiles, two target profiles, four literal intents, and separate relative+BPC
controls: 640 successful executions. Every corresponding C/Rust LCMS comparison
is exact. Argyll and MoxCMS differences are characterized, not treated as votes
on correctness. The minimal 836-byte qcms 2-point CMYK LUT is a retained outlier:
relative-intent maximum differences are 0.5675196647644043 for Argyll and
0.3399251401424408 for raw MoxCMS. Other profiles also disagree. Intent, BPC,
4D interpolation and destination clipping must be controlled before assigning
a cause. Production MoxCMS uses its existing target-dependent intent policy;
reports include explicit C intent comparisons so that policy is visible.

## Reproduction

`just cmyk-probes-build` builds the standalone Rust probes.
`just cmyk-probes-check` runs format, strict all-target Clippy and the shared
backend contracts. `just cmyk-c-oracle-build LCMS_REFERENCE FRESH_BINARY`
compiles the independent C evaluator, including native U8/U16 modes.
`just cmyk-native-compare EVALUATOR SOURCE INPUT REFERENCE RGB FRESH_JSON`
rechecks the exact existing native inputs. Run builds through the host's resource
wrapper with a separate Cargo output directory.

The [oxcms CMYK equipment](https://github.com/imazen/oxcms/blob/1bf631b8d494/tools/CMYK_ORACLE.md)
provides Argyll source/hash verification, the profile matrix, strided layout
runner and common-ICC native control. Source CMYK fixtures are existing oxcms
inputs; Argyll reference source/target profiles are explicitly fetched test data.
No reference-generated profile or image is added to the product bundle.

The compact [receipt](../benchmarks/cmyk_cms_2026-11-08.json) records source,
input and engine identities. Full reports, original failures and reference
executables are preserved outside git; RGB result planes are not generated by
these runners. Counts and scalar differences describe this witness set only.
No speed claim, release, merge, changed pixel threshold or new bundle is implied.
